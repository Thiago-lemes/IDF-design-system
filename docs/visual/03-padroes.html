Como a tela de venda reduz toques

Uma venda comum de café com pão de queijo leva 3 toques: o combo, Cobrar, Pix.

  • Abre já na venda, sem tela de início no meio.
  • Mais vendidos hoje no topo, calculados dos dados reais.
  • Combos de um toque e Repetir última.
  • Busca e código de barras sempre no foco; F2 cobra, Esc volta.
  • Dinheiro com notas rápidas e troco calculado.

Seções de destaque

Cada loja decide o que entra, o pacote só entrega o espaço e a regra de ordem.

  • Mais vendidos hoje (automático)
  • Combos e ofertas (a liderança cadastra)
  • Categorias como filtros de um toque
  • Acabando: selo de estoque no produto, para não vender o que não tem
Padrão 5

Erro sempre com mensagem, código e detalhes

Todo erro passa pelo mesmo painel. A pessoa lê o que aconteceu em português, vê o código estável e o número da requisição, e abre os detalhes técnicos. Teste cada caso.

Quem está vendo

Em sistema interno, a stack aparece sempre (aberta). Em sistema público, ela fica fora da tela e vai para o Sentry com o mesmo número de requisição. Veja o porquê mais abaixo.

O que o painel sempre mostra

  • Título e explicação em português, dizendo o efeito (“Nada foi cobrado”)
  • Código estável (ERRO_INTERNO), status e número da requisição
  • Detalhes técnicos com stack e botão Copiar detalhes
  • Ação clara: tentar de novo ou voltar
  • Também no ErrorBoundary, para a tela inteira que quebrar

Por que a stack muda no sistema público

Stack mostra caminhos de arquivo, bibliotecas e versões, e ajuda quem procura uma falha para explorar. Para a equipe autenticada, isso vale o risco: ela precisa agir. Para uma mãe no Kids IDF, só atrapalha. Se você quiser stack em todos, é uma chave no pacote (mostrarStack).

// regras da limpeza antes de exibir ou copiar (pacote @idf/ui)
limparStack(texto) {
  return texto
    .replace(/(https?:\/\/[^\s)]+)\?[^\s)]*/g, "$1?[removido]")  // query string
    .replace(/[\w.+-]+@[\w-]+\.[\w.]+/g, "[e-mail]")             // e-mails
    .replace(/(Bearer|token=|sessao=)[^\s&]+/gi, "$1[removido]") // credenciais
    .replace(/[A-Za-z]:\\[^\s)]+|\/(home|Users)\/[^\s)]+/g, "[caminho]")
    .split("\n").slice(0, 12).join("\n");                        // no máximo 12 linhas
}
Padrão 4

Front seguro por padrão

Como o front trata dinheiro e dados de pessoas, segurança vira regra do pacote, conferida no CI, e não decisão de cada dev. Parte disso o Pastinho já faz.

Proteção CSRFTodo envio que altera dados manda o cabeçalho X-Pastinho: 1 (no pacote, o nome é configurável).Já no Pastinho
CSP rígidascript-src 'self', sem unsafe-inline nem eval; frame-ancestors 'none'; X-Content-Type-Options, Referrer-Policy, Permissions-Policy.Cabeçalhos já no Pastinho; CSP do front entra
Nada de HTML cruProibido dangerouslySetInnerHTML e eval por regra de lint. Texto sempre escapado. Links externos com rel="noopener noreferrer".Regra de lint nova
