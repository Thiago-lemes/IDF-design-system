Igreja IDF · plataforma de sistemas

Uma família visual, dois registros.

O Kids IDF fala com pais e crianças, por isso é caloroso e arredondado. A Lojinha, o PDV e o Admin são ferramentas de trabalho: precisam de números legíveis, tabelas densas e telas que cansam pouco. O mesmo design system atende os dois, com um registro para cada público.

1 · Registros

Expressivo para fora, operacional para dentro

Um registro é um pacote de decisões que muda junto: tipografia de título, raio, densidade e quanto a cor de marca aparece.

Expressivo · uso externo

Kids IDF

  • Título: Bricolage Grotesque, peso 800
  • Forma: cantos de 14 a 26 px, sombra suave
  • Cor: índigo, sol e coral em áreas grandes
  • Toque: controles de 44 px, bastante respiro
  • Fundo: creme quente
Operacional · uso interno

Lojinha, PDV e Admin

  • Título: Figtree, peso 700 a 800 (a mesma fonte de texto)
  • Forma: cantos de 8 a 12 px, borda fina, quase sem sombra
  • Cor: neutros frios; a cor de marca só em ação e seleção
  • Densidade: 36 px no computador, 56 px no PDV (toque)
  • Números: sempre tabulares e alinhados à direita
1 · PRIMITIVOS

2 · SEMÂNTICOS

surface, text, line, brand, ok, warn, danger. O contrato dos componentes.

4 · PRODUTO

Só a cor de marca e o nome. Um arquivo pequeno por sistema.

Controles de 56 px, texto maior, uma ação principal por tela e atalhos de teclado (F2 cobrar, Esc cancelar) para quem usa leitor de código de barras.

5 · Amarração entre sistemas

O Admin é o painel que enxerga todos

Visual igual não basta: o Admin precisa de uma linguagem de dados comum para somar tudo. Duas regras mantêm isso simples.

Kids IDFLojinhaPDV→ login único e eventos padronizados →IDF Admin

Login único e seletor de apps

Uma conta, um menu “Meus sistemas” igual em todos os produtos, para ir de um a outro sem novo login. O visual do menu vem do pacote.

Contrato de eventos

Cada sistema publica o mesmo formato (sistema, evento, quando, valor, estado). A tabela “atividade recente” do Admin é só a leitura disso.

7 · Decisões para você

Antes de começar a codar

Qual a cor do comércio?

Lojinha e PDV com um mesmo teal, para parecerem uma só frente. Alternativa: usar o índigo da igreja em tudo que é interno.

Recomendo: teal na Lojinha e no PDV, índigo no Admin.

O PDV roda onde?

Tablet ou celular no balcão pede toque grande. Computador com leitor de código de barras pede teclado. Define se o PDV é touch-first.

Recomendo: touch-first, com atalhos de teclado.

O PDV funciona sem internet?

Venda em balcão não pode parar. Modo offline muda arquitetura de dados, não só tela.

Decidir cedo: o design system só precisa de um estado “sem conexão” pronto.

Um repositório para o pacote?

Pacote @idf/ui com tokens (CSS e JSON) e componentes React, versionado, consumido pelos quatro apps.

Recomendo: pacote próprio. Primeiro tokens, depois componentes.
